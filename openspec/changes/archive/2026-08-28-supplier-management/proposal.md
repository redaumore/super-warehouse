# Proposal: Supplier Management

## Intent

Suppliers lack CRUD UI, validation, and state. This adds master-data management, an English domain rename, and legacy data deletion (user decisions).

## Scope

### In Scope
- `suppliers` + `supplier_sku_mappings` (renamed) + new master-data columns — see table below.
- CRUD module `src/backoffice/suppliers.py` + sixth tab (clients.py pattern); form with reactive validation (code, margin, IVA).
- 3-char `code` autogenerated from `business_name`; editable; unique; immutable once linked.
- Pure helpers: CUIT mod-11, email, strict E.164 phone; whatsapp reuses `normalize_phone`.
- Soft delete via `status`; INACTIVO excluded from sourcing, PO creation, ingestion.
- One migration: rename + DELETE legacy supplier rows and dependents.

### Out of Scope
- Physical deletion; legacy preservation/backfill; replenishment; portal; DB-backed searcher; catalog re-pricing on margin edit.

## Capabilities

### New Capabilities
- `supplier-management`: master data, validation, codegen, soft-delete lifecycle.

### Modified Capabilities
- `backoffice`: sixth tab, quick search, status filter.
- `supplier-catalog-search`: candidates MUST exclude INACTIVO.
- `purchase-order-lifecycle`: refuse INACTIVO in `open_or_create_po`/`accumulate_need`.
- `supplier-document-ingestion`: `confirm_items` refuses INACTIVO.

## Approach

clients.py-style module + pure `src/supplier/` helpers; one migration; ACTIVO guards; contract-only searcher.

## Key Decisions

| Decision | Choice |
|---|---|
| CUIT | NULLable + partial unique index |
| Email | add `email-validator` |
| Phone | `whatsapp` → WhatsApp-form (`normalize_phone`); `phone` → strict E.164 (new helper) — user decision |
| Margin edit | future ingestions only — user decision |
| Code immutability | existence checks on the 4 linked models |
| Naming | English supplier domain — user decision |
| Code in views | `[COD] business_name` labels |
| DB searcher | contract-only |

## English Rename (normative)

| Old | New |
|---|---|
| `proveedores`/`Proveedor`, PK `proveedor_id` | `suppliers`/`Supplier`, PK `id` |
| `razon_social`, `contacto`, `telefono`, `margen_predeterminado`, `condiciones` | `business_name`, `contact_name`, `phone`, `default_margin_pct`, `terms` |
| `proveedor_sku_mapping`/`ProveedorSkuMapping` | `supplier_sku_mappings`/`SupplierSkuMapping` |
| `mapping_id`, `codigo_proveedor`, `descripcion_raw`, `sku_interno`, `confianza` | `id`, `supplier_sku_code`, `raw_description`, `internal_sku`, `confidence` |
| FK `proveedor_id` (catalogo, mapping); `Catalogo.proveedor` | `supplier_id`; `Catalogo.supplier` |
| — | New: `cuit`, `address`, `email`, `whatsapp`, `code`, `iva_condition`, `status` |

`supplier_purchase_orders.supplier_id`/`sourcing_needs.supplier_id` already English — FK target only. Other Spanish columns untouched.
